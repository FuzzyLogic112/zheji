# 遮迹：小范围需求与开源参考核验

核验日期：2026-09-26。范围：一个官方资料入口、两个开源项目；用于首版产品判断，不代表完整市场研究或安全认证。

## 已核实资料

1. [ICO：Disclosing documents to the public securely](https://ico.org.uk/for-organisations/uk-gdpr-guidance-and-resources/security/disclosing-documents-to-the-public-securely/)
   - 英国信息专员办公室的官方指引，适用情境包括在线公开文档和向客户发送文档。
   - 核心问题是可见内容之外还可能存在隐藏个人信息；分享前需要检查、移除或遮盖，并选择合适格式。
   - 这是一般文档分享指引，不能据此宣称某个截图工具已获认证或确保合规。
2. [ExifCleaner](https://github.com/szTheory/exifcleaner)
   - 已读取仓库说明并通过 GitHub 元数据核实为 MIT 许可。
   - 桌面应用，基于 ExifTool 清理图片、媒体和 PDF 元数据，提供清理前后检查。
   - 项目明确披露格式差异：例如 PDF 的原始元数据可能仍可恢复，部分格式有清理限制。可借鉴其可核验结果与限制说明，不能把“清理元数据”等同于“消除所有敏感信息”。
3. [AutoRedact](https://github.com/karant-dev/AutoRedact)
   - 已读取仓库说明并通过 GitHub 元数据核实为 GPL-3.0 许可。
   - README 描述浏览器内的 OCR 与规则检测、批量图片处理和 ZIP 导出；仓库同时描述可选 CLI/API 用法。
   - 证明浏览器端图片隐私处理已有开源实现；未执行其代码或审计其网络行为，不背书其准确率与隐私保证。仅作功能参考；本项目不复制其代码。

## 实际价值假设

用户把聊天、订单、物流、求助报错等截图分享给特定对象时，可能需要保留问题上下文，同时遮住姓名、地址、账号或令牌。一个中文、无需账号、手动操作的短流程，可能比打开通用图片编辑器更直接。

首版可用流程是：选择 PNG/JPEG → 手动框选敏感区域 → 以完全不透明色块覆盖 → 按需添加用途水印 → 预览并导出新的 PNG。用途水印用于表达接收人或用途，不能阻止转发、裁剪或截图。

上述需求合理性得到资料与既有项目的支持，但“用户会持续使用”和“现有工具不够方便”仍是待验证假设。不要宣传为首创、自动检测、绝不泄密或已获安全认证。

## 首版关键失败路径与验收建议

| 失败路径                                             | 应验证的结果                                                                                                                             |
| ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 预览缩放、反向拖动、边界裁切或 JPEG 朝向导致错位     | 导出遮盖区域与用户看到的图像坐标一致；矩形边缘向外取整，避免露出边缘像素。                                                               |
| 只在界面叠加色块，或色块继承了水印透明度             | 直接检查导出 PNG 像素；敏感区域被实色替换，覆盖色 alpha 为 255；导出不含可移除的图层或原图附件。                                         |
| 导出沿用原文件字节或元数据                           | 用带 EXIF/XMP/文本标记的合成输入验证输出；重新绘制并编码，不复制源文件元数据。允许编码器生成自身必要信息，避免笼统声称“没有任何元数据”。 |
| 用户漏选二维码、头像、上下文或画面其他信息           | 提供最终预览和人工复核提示。手动工具无法判断所有敏感信息；水印不替代遮盖。                                                               |
| 快速更换文件导致旧解码结果覆盖新图                   | 导入状态与当前文件绑定；换图后清除旧选择、历史记录和导出状态。                                                                           |
| 损坏、伪装格式或超大尺寸输入造成空白导出、内存占用   | 校验可解码格式与像素上限；失败时说明原因，不生成貌似成功的空白文件。                                                                     |
| 下载到旧版本、原图或带敏感名称的文件                 | 只允许导出当前扁平结果；采用通用结果文件名，完成后提示核对下载文件。                                                                     |
| 后续加入 CDN、统计、错误上报或持久化破坏本地处理承诺 | 检查构建资源和处理期间网络请求；默认不持久化图片，不发送图片、文件名或水印文本。                                                         |

最小验收材料可全部使用生成的虚构截图：一张含假地址/账号的图、一张带测试元数据的 JPEG、一张透明 PNG，以及损坏和超限文件。无需接触用户真实资料。
